# 家計簿

iPhone の Safari で使う個人用の家計簿です。Cloudflare Workers で画面とAPIを配信し、D1 に記録を、R2 に明細ファイルと控えを置き、Workers AI でカテゴリを決めます。無料枠に収まる前提で作っています。

記録は複式簿記の仕訳で持ちます。画面では支払方法とカテゴリを選ぶだけで、仕訳は裏で作ります。カテゴリも口座の一種として同じ表に置くので、カードでの買い物、引き落とし、チャージ、返品、回収がすべて同じ形で書け、どの口座の残高も仕訳の合計から出ます。

## できること

ホームには、手元のお金の合計からカードの未払いと次の返済を引いた使えるお金を出します。カードで払った分は利用した時点でこの額から減り、引き落とし日には口座の残高が減るだけで、この額は動きません。

カード払いの手入力は仮の取引になり、三井住友カード(Vpass)の明細CSVを取り込むと照合画面で4つに分けて結びつけます。候補が1件だけで日付と店名も合う行は自動で結びつけ、候補が複数ある行は選ぶまで取り込みません。電子マネーへのチャージは振替にします。CSVの読み取りとキーワード表は kuridanho/card-usage から移植しました。明細を取り込まないカード(家賃用など)は、口座の設定で取り込みを切ると手入力がそのまま確定になります。

カテゴリは、利用者が直した対応、AIが前に決めた対応、AI、キーワード表の順で決めます。AIは既存のカテゴリに合うものがなければ新しいカテゴリを作ります。カテゴリの追加、名前の変更、統合ができ、統合すると過去の取引と学んだ対応も移ります。

使い始めは、分かる口座の残高だけを開始残高として入れれば始められます。棚卸しで実際の残高を入れると差を出し、差額を使途不明の支出として揃えられます。投資の口座では差額を評価損益にし、支出には数えません。立て替えは総額を支出にして印を付け、回収するたびに食事をした月の支出から引きます。

集計の年は1月始まりと4月始まりを切り替えられます。月末のまとめを作ると、その後に過去の月が変わったときに、変わった額と理由を集計画面に出します。

来月の予算は、繰り返しの収入・支出、カードの引き落とし、借入の返済、記録済みの臨時の支出を読み、来月末の手元資金から貯金に回す額を引いて出します。カードの利用は来月の手元からは出ないので、ここでは引きません。

「貯金に回す額」は来月の予算の画面で変えられます。

毎日日本時間7時の Cron で、引き落とし日が来たカードと借入の引き落としを記録し、月初に前月のまとめを作り、全データをR2に控えます。

## 始め方

```sh
npm install
npx wrangler login
npx wrangler d1 create kakeibo          # 出てきた database_id を wrangler.jsonc に入れる
npx wrangler r2 bucket create kakeibo
npm run db:migrate:remote
npm run deploy
```

Workers の URL には Cloudflare Access(Zero Trust のアプリケーション)をかけ、自分のメールアドレスだけを通してください。アプリはこのとき付くメールアドレスを記録者として残します。API は Access が付けるメールのヘッダーが無ければ 401 を返すので、Access の対象から漏れたホスト名(`*.workers.dev` など)があっても記録は読めません。監視用の `/api/health` だけは認証なしで返します。

手元で動かすときは `npm run db:migrate:local` のあと、`.dev.vars` に次の1行を置いてから `npm run dev` です。Access を通らない手元だけ、この印で認証を外します。

```sh
echo 'ALLOW_LOCAL="1"' > .dev.vars
```

AI の binding は手元でも Cloudflare に接続するため、`wrangler login` が要ります。テストは `npm test` で、Workers の実行環境の中で D1 を使って動きます。

GitHub で PR をマージしただけでは、本番の Worker は更新されません。default branch を最新にしてから `npm run deploy` を実行してください。ホーム画面のアプリは Service Worker が古い画面を返すことがあるので、更新後は一度アプリを閉じて開き直してください。

## レシート読み取りモデルの比較

レシート読み取りを作る前に、実物のレシートで Workers AI の視覚モデルを比べるための仕組みがあります。`ENABLE_RECEIPT_EVAL` は既定で `"0"` です。比べるときだけ `"1"` にしてデプロイし、画像と正解の `expected.csv` を置いたフォルダを指定して実行します。1回のリクエストで最大4モデル・8MB の画像まで受け付けます。

```sh
node scripts/receipt-eval.mjs --url https://kakeibo.<you>.workers.dev --dir ./receipts
```

モデルごとに合計と日付の一致率、品目の和が合計と合う割合、平均の時間とトークン数、1枚あたりの Neurons の見積もりを表に出します。検証が終わったら `ENABLE_RECEIPT_EVAL` は `"0"` に戻してください。
